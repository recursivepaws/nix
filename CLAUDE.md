# NixOS Configuration

Personal NixOS config for three machines (`amanita`, `hericium`, `ampulex`) using the
[Den](https://github.com/vic/den) flake framework on top of NixOS + home-manager.

## Rebuilding

```bash
# Rebuild and switch (primary machine)
nix run .#amanita -- switch

# Validate syntax without building
# NOTE: full check fails off-hericium — its boot.initrd.secrets references
# /ssd-keyfile, which only exists on that machine. Eval per-host instead:
#   nix eval .#nixosConfigurations.amanita.config.system.build.toplevel.drvPath
nix flake check --no-build

# Regenerate flake.nix (auto-generated — never edit it directly)
nix run .#write-flake
```

> `flake.nix` is auto-generated by `flake-file`. All flake inputs are declared
> via `flake-file.inputs.*` inside individual module files. After adding or
> changing an input, run `nix run .#write-flake` to regenerate it.

## Den framework primer

Den organizes config into **aspects** — composable units with typed output classes:

```nix
den.aspects.my-aspect = {
  nixos       = { pkgs, config, ... }: { /* NixOS module */ };
  homeManager = { pkgs, config, lib, ... }: { /* home-manager module */ };
  user        = { extraGroups = [ ... ]; };   # user account config

  includes = [ den.aspects.other-aspect ];    # pull in another aspect

  # Cross-entity delivery: push config from this aspect to all hosts
  provides.to-hosts.nixos = { pkgs, ... }: { /* NixOS module */ };

  # Cross-entity delivery: push config to all users of hosts using this aspect
  provides.to-users.includes = with den.aspects; [ foo bar ];
};
```

Key rules:
- `nixos` → emitted into the host's NixOS config
- `homeManager` → emitted into the user's home-manager config
- `user` → merged into the NixOS `users.users.<name>` declaration
- `includes` → pulls in other aspects (resolved transitively)
- `provides.to-hosts` / `provides.to-users` → cross-entity delivery

## Machines

| Host | Arch | Users | Role |
|------|------|-------|------|
| `amanita` | x86_64-linux | `vera`, `work` (primary) | Primary workstation (System76), Hightouch dev |
| `hericium` | x86_64-linux | `vera` (primary), `work` | Desktop (AMD GPU, audio production, gaming) |

Declared in `modules/hosts/hosts.nix`. Config shared by all hosts (dev toolchain
packages, openssh, pipewire, 1password, session vars) lives in `den.default.nixos`
in `modules/default/default.nix` — host files hold only host-specific config.

## MCP tools available

### `mcp__plugin_claude-code-home-manager_nixos__nix`

Use this to look up NixOS/home-manager options and packages without leaving the session:

```
# Search for a package
action: search, query: "certutil", source: nixos, type: packages

# Look up a NixOS option
action: info, query: "virtualisation.docker", source: nixos, type: options

# Look up a home-manager option
action: info, query: "programs.google-chrome", source: home-manager, type: options

# Search flake inputs
action: flake-inputs, query: "den", source: flakes
```

Always prefer this over guessing package names or option paths.

### `mcp__plugin_claude-code-home-manager_filesystem__*`

Grants read/write access to `~/Software`. Use for reading Hightouch source files
(e.g. `~/Software/hightouch/`) without needing Bash.

## Common patterns

### Adding a system package

```nix
# In the relevant aspect's nixos block, or modules/default/default.nix
environment.systemPackages = with pkgs; [ my-package ];
```

### Adding a home-manager package

```nix
# In the relevant aspect's homeManager block
home.packages = with pkgs; [ my-package ];
```

### Adding a new aspect

1. Create `modules/aspects/my-aspect.nix` (or directory with `default.nix`)
2. It will be auto-imported via `import-tree` — no manual registration needed
3. Reference it via `den.aspects.my-aspect` in other aspects or in `den.default.includes`

### Adding a new MCP server (work user only)

Edit `modules/aspects/claude.nix` — add to `mcp-servers.settings.servers` inside the
`lib.optionalAttrs isWork { ... }` block.

### Referencing a secret

Secrets are managed with `agenix` (ragenix wrapper). See `modules/default/ragenix.nix`
and the `secrets/` directory. At runtime, secrets land at `/run/agenix/<name>`.
The agent env (API keys etc.) is sourced from `/run/agenix/agent-env` — this is what
the `claude()` zsh wrapper in `claude.nix` loads before launching Claude Code.

## Flake inputs of note

| Input | Purpose |
|-------|---------|
| `den` | Core framework |
| `nixpkgs` | nixpkgs-unstable channel |
| `nixpkgs-node` | Pinned nixpkgs for Node.js 20 (Hightouch constraint) |
| `home-manager` | Follows nixpkgs |
| `agenix` | Secret management |
| `claude-plugins-nix` | Claude Code plugin manager + skills installer |
| `mcp-servers-nix` | Declarative MCP server configuration |
| `niri-flake` | Niri Wayland compositor |
| `flake-file` | Auto-generates `flake.nix` from module-declared inputs |
| `import-tree` | Auto-imports all `.nix` files under `modules/` |
